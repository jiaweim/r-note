## 引言

良好的代码风格就像标点符号：没有也能写，但有了让代码更易读。即使刚学编程，也应该尽早养成一致的代码风格。这不仅方便他人和未来的自己阅读，在向他人求助时也尤为重要。本章介绍 `tidyverse` 风格指南的核心要点，这也是贯穿全书的规范。

## 1. 命名规范

2.3 节简要提过命名规则：变量名（用 `<-` 或 `mutate()` 创建）只用小写字母、数字和下划线（`_`）。多单词变量名用 `_`分隔。

```R
# 推荐
short_flights <- flights |> filter(air_time < 60)

# 避免
SHORTFLIGHTS <- flights |> filter(air_time < 60)
```

优先选择长且描述性强的名称，不要为省打字用简短名称。简短变量名省不了多少打字时间（自动补全很轻松），而晦涩缩写会耗费大量时间去猜测。

一组相关变量名应保持一致。人容易忘记命名约定，导致前后不一致，必要时应当重命名。一般来说，同类变量最好加上相同**前缀**而非后缀，因为自动补全匹配变量名开头效果最好。

## 2. 空格

除乘方运算符 `^` 外，其他数学运算符（`+`、`-`、`==`、`<` 等）两侧都加空格；赋值运算符（`<-`）两侧也加空格。

```R
# 推荐
z <- (a + b)^2 / d

# 避免
z<-( a + b ) ^ 2/d
```

调用普通函数时，括号内外不加空格；逗号后加一个空格，与英文书写习惯一样。

```R
# 推荐
mean(x, na.rm = TRUE)

# 避免
mean (x ,na.rm=TRUE)
```

如果多加空格能让代码更整齐，也可以。例如在 `mutate()` 中创建多个变量时，可加空格使所有等号（`=`）上下对齐，方便快速浏览。

```R
flights |> 
  mutate(
    speed      = distance / air_time,
    dep_hour   = dep_time %/% 100,
    dep_minute = dep_time %%  100
  )
```

## 3. 管道符

管道符 `|>` 前面留一个空格，管道符通常放在行末。这样便于增删、重排步骤，也能通过左侧动词快速把握整体代码流程。

```R
# 推荐
flights |>  
  filter(!is.na(arr_delay), !is.na(tailnum)) |> 
  count(dest)

# 避免
flights|>filter(!is.na(arr_delay), !is.na(tailnum))|>count(dest)
```

- 若管道符传入的函数有命名参数（如 `mutate()` 或 `summarize()`），请将每个参数单独一行；
- 若无命名参数（如 `select()` 或 `filter()`），则尽量放一行，放不下再分行。

```R
# 推荐
flights |>  
  group_by(tailnum) |> 
  summarize(
    delay = mean(arr_delay, na.rm = TRUE),
    n = n()
  )

# 避免
flights |>
  group_by(
    tailnum
  ) |> 
  summarize(delay = mean(arr_delay, na.rm = TRUE), n = n())
```

在管道操作的第一步后，每行缩进两个空格（RStudio 会自动完成）。每个参数单独一行时，再额外缩进两个空格。同时右括号 `)` 单独一行，并取消缩进，从而与函数名对齐。

```R
# 推荐
flights |>  
  group_by(tailnum) |> 
  summarize(
    delay = mean(arr_delay, na.rm = TRUE),
    n = n()
  )

# 避免
flights|>
  group_by(tailnum) |> 
  summarize(
             delay = mean(arr_delay, na.rm = TRUE), 
             n = n()
           )

# 避免
flights|>
  group_by(tailnum) |> 
  summarize(
  delay = mean(arr_delay, na.rm = TRUE), 
  n = n()
  )
```

能写在一行时，偶尔可以不遵守这些排版规则。但根据经验，简短代码往往会随着需求增加而变得越来越长。因此，一开始就换行排版通常更省时间。

```R
# 紧凑一行
df |> mutate(y = x + 1)

# 虽然占 4 行，但便于日后扩展
df |> 
  mutate(
    y = x + 1
  )
```

管道操作不要超过 10 到 15 行，尽量拆成更小的子任务，并为每个任务起描述性名称，便于理解和检查中间结果。

尽量为数据对象起描述性名称，尤其在结构发生根本变化后（如 `pivot`、 `summarize` 之后）。

**不必一次完美**！如果有可命名的中间状态，就拆分长管道。

## 4. ggplot2

管道符的排版规则同样适用于 `ggplot2`：只需把 `+` 当 `|>`对待即可。

```R
flights |> 
  group_by(month) |> 
  summarize(
    delay = mean(arr_delay, na.rm = TRUE)
  ) |> 
  ggplot(aes(x = month, y = delay)) +
  geom_point() + 
  geom_line()
```

如果函数参数无法放在同一行，就每个参数单独一行：

```R
flights |> 
  group_by(dest) |> 
  summarize(
    distance = mean(distance),
    speed = mean(distance / air_time, na.rm = TRUE)
  ) |> 
  ggplot(aes(x = distance, y = speed)) +
  geom_smooth(
    method = "loess",
    span = 0.5,
    se = FALSE, 
    color = "white", 
    linewidth = 4
  ) +
  geom_point()
```

注意 `|>` 与 `+` 的衔接。我们希望无需这种切换，但 `ggplot2` 早于管道符出现，所以只能如此。
