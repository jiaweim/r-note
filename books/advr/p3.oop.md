## 简介

接下来的五章介绍面向对象编程（OOP）。与其他编程语言相比，在 R 语言中进行 OOP 会稍微困难一些，原因如下：

- **有多种 OOP 系统可供选择。** 在本书中，我将重点介绍我认为最重要的三种：S3、R6 和 S4。其中 S3 和 S4 由 base R 提供；R6 由 `R6` 包提供，它与 base R 中的引用类（Reference Classes，简称 RC）类似。
- **各个 OOP 系统的相对重要性存在争议。** 我认为 S3 最重要，其次是 R6，最后是 S4。而另一些人则认为 S4 最重要，其次是 RC，并主张尽量避免使用 S3。这意味着不同的 R 语言社区会使用不同的系统。
- **底层机制的差异。** S3 和 S4 使用的是泛型函数 OOP（generic function OOP），这与当今大多数流行语言使用的封装式 OOP（encapsulated OOP）有很大不同。简而言之，尽管 OOP 的底层理念在各语言中是相通的，但其具体实现方式却大相径庭。这意味着你无法直接将现有的 OOP 技能无缝迁移到 R 语言中。

在 R 语言中，函数式编程通常比面向对象编程更为重要，因为你通常是通过将复杂问题分解为简单的函数，而不是简单的对象来解决它们的。尽管如此，学习这三种系统仍有其重要原因：

- **S3** 允许你的函数返回丰富的结果，这些结果既具有对用户友好的显示方式，又具有对程序员友好的内部结构。S3 在整个 base R 中被广泛使用，因此如果你想扩展 base R 的函数以处理新类型的输入，掌握 S3 就显得尤为重要。
- **R6** 提供了一种标准化的方式来规避 R 语言的“修改时复制”（copy-on-modify）语义。如果你想对独立于 R 存在的对象进行建模，这一点尤为关键。如今，R6 的一个常见应用场景是对来自 Web API 的数据进行建模，这些数据的变化可能来自 R 的内部或外部。
- **S4** 是一个严谨的系统，它迫使你仔细思考程序设计。它特别适合构建随时间演进且会有众多程序员参与贡献的大型系统。这也是 Bioconductor 项目采用 S4 的原因，因此学习 S4 的另一个原因是为你参与该项目做好准备。

这个简短的引言章节旨在介绍重要的专业词汇，以及一些在实际应用中识别 OOP 系统的工具。随后的章节将深入探讨 R 语言 OOP 系统的细节：

- **第 12 章** 介绍基础类型（base types），它们构成了所有其他面向对象系统的底层基础。
- **第 13 章** 介绍 S3，这是最简单且最常用的面向对象系统。
- **第 14 章** 讨论 R6，这是一种基于环境（environments）构建的封装式面向对象系统。
- **第 15 章** 介绍 S4，它与 S3 类似，但更加正式和严格。
- **第 16 章** 对这三种主要的面向对象系统进行了比较。通过了解每种系统的权衡，能更好地把握何时该使用哪一种。

本书侧重于面向对象编程的底层机制，而非其实际应用技巧。如果你之前没有面向对象编程的经验，要完全理解本章内容可能会有些困难。你可能会疑惑为什么我没有提供更多立竿见影的实用内容。我之所以在这里专注于底层机制，是因为这些内容需要在某处得到详尽的阐述（编写这几章需要我进行大量的阅读、探索和知识整合）；而如何有效地使用 OOP 极其复杂，足以写成一整本书；在《Advanced R》中确实没有足够的篇幅来进行如此深度的探讨。

## 面向对象编程（OOP）系统

不同的人对 OOP 术语的使用方式各不相同，因此本节将快速概述一些重要的专业词汇。

使用 OOP 的主要原因是**多态性**（polymorphism）。多态性意味着开发者可以将函数的接口（interface）与其具体实现（implementation）分离开来，从而使得同一个函数形式能够处理不同类型的输入。这与**封装**（encapsulation）的理念密切相关：用户无需关心对象的内部细节，细节被封装在了一个标准的接口背后。

例如，多态性使得 `summary()` 函数能够对数值型变量和因子型变量输出不同的结果：

```r
diamonds <- ggplot2::diamonds

summary(diamonds$carat)
#>    Min. 1st Qu.  Median    Mean 3rd Qu.    Max. 
#>    0.20    0.40    0.70    0.80    1.04    5.01

summary(diamonds$cut)
#>      Fair      Good Very Good   Premium     Ideal 
#>      1610      4906     12082     13791     21551
```

你可以设想 `summary()` 内部包含了一系列 `if-else` 语句，但那样的话，只有最初的作者才能添加新的实现。而 OOP 系统使得任何开发者都能为新的输入类型扩展该接口并提供相应的实现。

更准确地说，在面向对象系统中，对象的类型被称为**类**（class），而针对特定类的具体实现被称为**方法**（method）。类定义了对象“是什么”，而方法描述了该对象“能做什么”。类定义了字段（fields），即该类的每个实例所拥有的数据。类被组织成层级结构（hierarchy）：如果某个类没有定义某个方法，系统就会使用其父类的方法，这被称为子类**继承**了父类的行为。例如，在 R 语言中，有序因子（ordered factor）继承自普通因子（factor），广义线性模型（generalised linear model）继承自线性模型（linear model）。根据给定的类来寻找正确方法的过程被称为**方法分派**（method dispatch）。

面向对象编程主要有两种范式，它们的区别在于方法和类之间的关联方式。在本书中，我们将这两种范式分别称为**封装式**（encapsulated）和**函数式**（functional）：

- 在**封装式 OOP** 中，方法属于对象或类，方法调用的形式通常是 `object.method(arg1, arg2)`。之所以称为“封装式”，是因为对象同时封装了数据（通过字段）和行为（通过方法），这也是当今大多数流行语言所采用的范式。
- 在**函数式 OOP** 中，方法属于泛型函数（generic functions），方法调用的形式看起来就像普通的函数调用：`generic(object, arg2, arg3)`。之所以称为“函数式”，是因为从外部看它就像一个常规的函数调用，且在内部其组件也是函数。

掌握了这些术语，我们现在就可以精确地讨论 R 语言中可用的不同 OOP 系统了。

## R 语言中的 OOP

R 语言基础环境（base R）提供了三种 OOP 系统：S3、S4 和引用类（RC）：

- **S3** 是 R 语言最早的 OOP 系统。S3 是函数式 OOP 的一种非正式实现，它依赖于普遍的约定，而非强制保证。这使得它很容易上手，为解决许多简单问题提供了一种低成本的方式。
- **S4** 是对 S3 的一种正式且严谨的重写，在《Programming with Data》一书中被引入。与 S3 相比，S4 需要更多的前期准备工作，但作为回报，它提供了更多的保证和更强的封装性。S4 在基础包 `methods` 中实现，该包随 R 语言一同安装。
  *（你可能会好奇 S1 和 S2 是否存在。答案是不存在：S3 和 S4 是根据它们所伴随的 S 语言的版本来命名的。S 语言的前两个版本没有任何面向对象框架。）*
- **RC**（引用类）实现了封装式 OOP。RC 对象是一种特殊类型的 S4 对象，同时它们是可变的（mutable）。也就是说，它们不使用 R 语言常规的“修改时复制”（copy-on-modify）语义，而是可以在原处被修改。这使得它们更难以进行逻辑推理，但也使得它们能够解决在 S3 和 S4 的函数式 OOP 风格中难以解决的问题。

除了 base R，CRAN 上的扩展包还提供了一些其他的 OOP 系统：

- **R6** 实现了类似 RC 的封装式 OOP，但解决了一些重要的问题。在本书中，你将学习 R6 而不是 RC，具体原因将在 14.5 节中阐述。
- **R.oo** 在 S3 之上提供了一些形式化机制，并使得创建可变的 S3 对象成为可能。
- **proto** 实现了另一种基于原型（prototypes）的 OOP 风格，这种风格模糊了类与类的实例（即对象）之间的界限。我曾短暂地迷恋过基于原型的编程，并在 `ggplot2` 中使用过它，但现在我认为坚持标准形式是更好的选择。

除了被广泛使用的 R6 之外，这些系统主要具有理论上的研究价值。它们确实有各自的优点，但很少有 R 用户了解并理解它们，因此其他人很难阅读你的代码并为其做出贡献。

## sloop 包

在继续深入之前，我想先介绍一下 `sloop` 包：

```r
library(sloop)
```

`sloop` 包（“sail the seas of OOP”，即“在 OOP 的海洋中航行”）提供了一些辅助工具，弥补了 base R 中的缺失功能。其中第一个是 `sloop::otype()`。它可以让你轻松弄清楚一个“野生捕获”（wild-caught，即你在代码中偶然遇到）的对象使用的是哪种 OOP 系统：

```r
otype(1:10)
#> [1] "base"

otype(mtcars)
#> [1] "S3"

mle_obj <- stats4::mle(function(x = 1) (x - 2) ^ 2)
otype(mle_obj)
#> [1] "S4"
```

你可以使用这个函数来判断应该阅读本书的哪一章，以了解如何处理现有的对象。
