## 引言

## 1. 命名规范

我们在 2.3 节中曾简要地提到过命名规则。请记住，变量名（无论是通过 `<-` 创建的，还是通过 `mutate()` 创建的）都应当只使用小写字母、数字和下划线（`_`）。当变量名中包含多个单词时，请使用下划线（`_`）来进行分隔。

```R
# Strive for:
short_flights <- flights |> filter(air_time < 60)

# Avoid:
SHORTFLIGHTS <- flights |> filter(air_time < 60)
```

作为一条通用的经验法则，**优先选择长且描述性强、易于理解的名称，要好过选择那些仅仅为了打字快的简短名称**。简短的变量名在编写代码时节省的时间其实非常有限（尤其是现在的自动补全功能会帮你轻松打完），但当你回过头来看旧代码时，那些晦涩的缩写反而会耗费你大量的时间去猜测和破译。

如果你有一组相关事物的变量名，请尽量保持一致性。人总会忘记之前定下的命名约定，导致前后不一致，所以如果不得不回头去重命名，千万别觉得有心理负担。一般来说，如果你有一组属于同一类别的变量，**最好给它们加上相同的“前缀”而不是“后缀”**，因为自动补全功能在匹配变量名开头时效果最好。

## 2. 空格

除了乘方运算符 `^` 之外，请在其他所有数学运算符（如 `+`、`-`、`==`、`<` 等）的两侧都加上空格。同样，在赋值运算符（`<-`）的两侧也要加上空格。

```R
# Strive for
z <- (a + b)^2 / d

# Avoid
z<-( a + b ) ^ 2/d
```

在调用普通函数时，不要在括号的内部或外部加空格。另外，逗号后面一定要加一个空格，这和标准的英文书写习惯是一样的。

```R
# Strive for
mean(x, na.rm = TRUE)

# Avoid
mean (x ,na.rm=TRUE)
```

如果多加几个空格能让代码对齐得更好看，这也是完全可以的。例如，当你在 `mutate()` 中同时创建多个变量时，你可能会想加些空格，让所有的等号（`=`）上下对齐。这样能让代码更容易被快速浏览。

```R
flights |> 
  mutate(
    speed      = distance / air_time,
    dep_hour   = dep_time %/% 100,
    dep_minute = dep_time %%  100
  )
```

## 3. 管道符

管道符 `|>` 的前面必须保留一个空格，并且通常应该放在一行的末尾。这样的排版方式能让你更方便地添加新步骤、重新排列现有步骤、修改某个步骤中的元素；同时，当你只需快速扫视左侧的动词时，也能轻松获得对整体代码流程的宏观把握（全局视角）。

```R
# Strive for 
flights |>  
  filter(!is.na(arr_delay), !is.na(tailnum)) |> 
  count(dest)

# Avoid
flights|>filter(!is.na(arr_delay), !is.na(tailnum))|>count(dest)
```

如果你通过管道符传入的函数带有命名参数（比如 `mutate()` 或 `summarize()`），请将每个参数都放在单独的一行。如果函数没有命名参数（比如 `select()` 或 `filter()`），则尽量将所有内容保持在同一行；除非一行放不下，这种情况下才需要将每个参数分别放在单独的一行。

```R
# Strive for
flights |>  
  group_by(tailnum) |> 
  summarize(
    delay = mean(arr_delay, na.rm = TRUE),
    n = n()
  )

# Avoid
flights |>
  group_by(
    tailnum
  ) |> 
  summarize(delay = mean(arr_delay, na.rm = TRUE), n = n())
```

在管道操作的第一步之后，后续每一行都应缩进两个空格。在输入 `|>` 并按下回车键换行后，RStudio 会自动为你添加这些缩进空格。如果你将每个参数都放在单独的一行，请再额外缩进两个空格。同时，请确保右括号 `)` 单独占一行，并且取消缩进，使其水平位置与函数名对齐。

```R
# Strive for 
flights |>  
  group_by(tailnum) |> 
  summarize(
    delay = mean(arr_delay, na.rm = TRUE),
    n = n()
  )

# Avoid
flights|>
  group_by(tailnum) |> 
  summarize(
             delay = mean(arr_delay, na.rm = TRUE), 
             n = n()
           )

# Avoid
flights|>
  group_by(tailnum) |> 
  summarize(
  delay = mean(arr_delay, na.rm = TRUE), 
  n = n()
  )
```

如果你的管道操作能轻松写在一行内，偶尔不遵守这些排版规则也是可以的。但根据我们的经验，原本简短的代码片段往往会随着需求增加而变得越来越长。因此，一开始就预留好所有需要的垂直空间（换行排版），从长远来看通常会为你节省更多时间。

```R
# This fits compactly on one line
df |> mutate(y = x + 1)

# While this takes up 4x as many lines, it's easily extended to 
# more variables and more steps in the future
df |> 
  mutate(
    y = x + 1
  )
```

最后，要警惕写出过长的管道操作，比如超过 10 到 15 行。尽量将其拆分为更小的子任务，并为每个任务起一个具有描述性的名称。这些名称能帮助读者快速了解当前正在执行的操作，同时也更容易检查中间结果是否符合预期。

只要条件允许，你就应该为数据对象起一个描述性的名称。例如，当你从根本上改变了数据的结构时（比如在进行了数据透视 `pivot` 或汇总 `summarize` 之后），就非常值得这么做。

不要指望一次就能做到完美！如果管道中存在可以被赋予好名字的中间状态，你就应该把长管道拆分开来。

## 4. ggplot2

适用于管道符（pipe）的基本排版规则，同样也适用于 `ggplot2`；你只需要把加号（`+`）当作管道符（`|>`）一样对待即可。

```R
flights |> 
  group_by(month) |> 
  summarize(
    delay = mean(arr_delay, na.rm = TRUE)
  ) |> 
  ggplot(aes(x = month, y = delay)) +
  geom_point() + 
  geom_line()
```

同样地，如果你无法将某个函数的所有参数都塞进同一行，那就请把每个参数都放在单独的一行：

```R
flights |> 
  group_by(dest) |> 
  summarize(
    distance = mean(distance),
    speed = mean(distance / air_time, na.rm = TRUE)
  ) |> 
  ggplot(aes(x = distance, y = speed)) +
  geom_smooth(
    method = "loess",
    span = 0.5,
    se = FALSE, 
    color = "white", 
    linewidth = 4
  ) +
  geom_point()
```

请注意 `|>` 和 `+` 之间的衔接过渡。我们希望这种切换是不必要的，但遗憾的是，`ggplot2` 是在管道符（pipe）被发现之前就已经写好了。

## 5. 分节注释

随着你的脚本变得越来越长，你可以使用分节注释（sectioning comments）将文件拆分成易于管理的部分：

```R
# Load data --------------------------------------

# Plot data --------------------------------------
```

RStudio 提供了一个快捷键来创建这些标题注释（Mac 系统为 `Cmd + Shift + R`，Windows/Linux 系统为 `Ctrl + Shift + R`），并且会在编辑器左下角的代码导航下拉菜单中显示它们，如图 4.2 所示。

## 6. 本章小结

在本章中，你学习了代码风格最重要的原则。一开始，你可能会觉得这些规则有些武断（事实上，它们确实是一套人为制定的规则！），但随着时间的推移，当你编写了更多的代码，并与更多人共享代码时，你就会明白保持一致的代码风格有多么重要。另外，别忘了 `styler` 这个 R 语言扩展包：它是快速改善排版糟糕的代码质量的绝佳工具。

在下一章中，我们将回归数据科学工具，学习什么是‘整洁数据’（tidy data）。整洁数据是一种组织数据框（data frames）的标准化方法，在整个 `tidyverse` 生态中都被广泛使用。这种一致性会让你的工作变得更轻松，因为一旦你的数据是整洁的，它就能与绝大多数的 `tidyverse` 函数完美兼容。当然，现实往往没那么简单，你在实际中遇到的大多数数据集通常都不是整洁的。因此，我们还会教你如何使用 `tidyr` 包，将不整洁的数据转换为整洁数据。
