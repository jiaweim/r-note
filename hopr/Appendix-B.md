# 附录B：R 包

2026-04-09⭐

***
R 中很多函数不会在启动 R 时自动加载，而是存放在**程序包**中，需要在 R 基础环境之外另行安装。R 程序包类似于 C、C++ 和 JavaScript 中的库、Python 中的包以及 Ruby 中的 gem。一个 R 程序包会将实用函数、帮助文档与数据集打包在一起。一旦加载了对应的程序包，就可以在自己的 R 代码中调用这些函数。通常，一个 R 程序包中的所有内容都围绕某一类任务设计，用于专门解决这类问题。借助 R 程序包，你可以充分利用 R 最核心的优势：一是拥有庞大的程序包开发社区（其中许多是活跃的数据科学家），二是可以直接使用现成的代码流程，处理各类常见（乃至特殊）的数据科学任务。

> [!TIP]
>
> **Base R**
>
> 你可能会听过 **base R**。base R 是每次启动 R 时会自动加载的 R 函数集合。这些函数提供了 R 的基础功能，使用它们无需额外加载任何程序包。

## B.1 安装程序包

要使用 R 包，必须先安装，然后在当前的 R 会话中加载它。安装 R 包最简单的方法是使用 R 函数 `install.packages`。打开 R 并在命令行中输入如下内容：

```R
install.packages("<package name>")
```

该操作会在 **CRAN** 网站托管的程序包库中搜索你指定的包。当 R 找到该包后，会将其下载到你电脑上的库文件夹中。之后的 R 会话里，R 可以直接调用这个包，无需再次安装。任何人都可以编写 R 包并按自己的方式发布，但几乎所有 R 包都是通过 CRAN 网站发布的。CRAN 在发布前会对每个 R 包进行测试。这虽然不能完全消除包中的所有漏洞，但可以确保 CRAN 上的包可以在你操作系统的当前 R 版本中正常运行。

可以使用 R 的拼接函数 `c` 将多个包名组合在一起，实现**一次性安装多个包**。例如，若要安装 `ggplot2`、`reshape2` 和 `dplyr` 这三个包，可运行如下代码：

```R
install.packages(c("ggplot2", "reshape2", "dplyr"))
```

如果这是你第一次安装程序包，R 会提示你选择一个在线镜像站点进行安装。镜像站点会按地理位置列出。选择离你最近的镜像，下载速度通常会最快。如果你想下载新发布的包，可以先尝试 Austria 镜像。这是 CRAN 的主仓库，新包有时需要过几天才会同步到其他所有镜像站点。

## B.2 加载程序包

安装一个程序包不会让它的函数可以直接使用，只是把这些文件存到了你的电脑上。要使用某个 R 包，你还需要在当前 R 会话中用以下命令加载它：

```R
library(<package name>)
```

注意，这里没有引号。你也可以保留引号，但在 `library` 命令中引号是可选的（在 `install.packages` 命令中引号是比选的）。

`library` 命令会将该程序包的所有函数、数据集和帮助文件加载到当前 R 会话中，直到你关闭会话为止。下次启动新的 R 会话时，如果需要再次使用该包，必须用 `library` 重新加载，但**不需要再次安装**。每个包只需要安装一次，安装后就会一直保存在你的 R 库中。想要查看当前 R 库中已安装的所有包，可以运行以下命令：

```R
library()
```

`library()` 还会显示 R 库的路径，也就是存放 R 程序包的文件夹。你可能会看到很多自己并没印象安装过的包，这是因为在首次安装 R 时，系统会自动下载一批常用的程序包。

> [!TIP]
>
> **从（几乎）任意位置安装程序包**
>
> R 语言的 **devtools** 扩展包可以让你轻松地从 CRAN 官网以外的来源安装程序包。devtools 提供了诸如 `install_github`、`install_gitorious`、`install_bitbucket` 和 `install_url` 等函数。它们的用法与 `install.packages` 相似，只是会在其他平台上搜索 R 包。
>
> 其中 `install_github` 尤为实用，因为许多 R 开发者会在 GitHub 上发布包的开发版本。开发版通常会提前包含新函数与修复补丁，但稳定性和漏洞情况可能不如发布在 CRAN 上的正式版本。

为什么 R 要让你费心去安装和加载程序包呢？你可以设想一下：如果 R 把所有程序包都预先加载好，那它会变成一个非常庞大且运行缓慢的程序。截至 2026 年 4 月 9 日，CRAN 网站上已有 23571 个程序包。只在需要时安装并加载你要使用的包，会简洁得多。这样能让你的 R 运行更流畅，因为不需要检索过多的函数和帮助文档。这种设计还有其他好处。例如，你可以单独更新某个 R 程序包，而不必更新整个 R 软件。

> [!TIP]
>
> **了解 R 程序包的最佳方式**
>
> 如果不知道某个 R 包的存在，你就很难用上它。你可以访问 CRAN 官网，点击 “Packages” 链接查看可用包列表，但需要从数千个包中逐一筛选。此外，很多 R 包实现的功能是相似的。
>
> 如何判断哪个包最实用？**R 程序包邮件列表**是一个起点，它会推送新包发布通知，并保存历史公告存档。聚合 R 相关文章的博客也能提供有价值的线索，我推荐 **R-bloggers**。RStudio 在其支持网站（http://support.rstudio.com）的 “入门” 板块中，整理了一批最实用的 R 包清单。最后，CRAN 会按主题领域对一批最实用、最受认可的程序包进行归类，这是了解适用于你工作领域的 R 包的绝佳途径。
